# n-worker

> Claude Code 스킬 - 세션이 끝나도 프로젝트 내용을 기억하고, 코드를 쓰기 전에 스스로 계획을 검증하는 코드 작업 워크플로우.
>
> A Claude Code skill that remembers your project across sessions and adversarially reviews its own plan before writing code. (Korean-language skill)

## 왜 필요한가

Claude Code 로 무거운 작업(기능 추가, 리팩토링, 설계가 필요한 버그수정)을 하다 보면 반복되는 문제가 있다:

- **매 세션이 백지에서 시작한다.** 프로젝트 구조, 컨벤션, 지난달에 밟았던 함정을 매번 다시 설명하거나, 설명을 빼먹고 사고가 난다.
- **모호한 요청은 재작업이 된다.** 의도를 임의로 해석해서 만든 결과물은 대부분 다시 만들게 된다.
- **코드부터 쓰고 나서 후회한다.** 구조 위반, 중복 구현, 놓친 회귀는 코드가 이미 쌓인 뒤에 발견되면 비싸다.
- **긴 세션은 컨텍스트 비용이 샌다.** 대화가 길어질수록 같은 내용이 매 턴 재전송된다.

n-worker 는 이 네 가지를 각각 장기기억, 인터뷰, 사전 리뷰, 컨텍스트 경제로 해결하는 대화형 파이프라인이다.

## 무엇을 얻는가

- **프로젝트별 장기기억** - `notebook/` 에 확인된 사실만 3층(공통 / 스택 / 프로젝트)으로 누적한다. 다음 세션은 설명 없이 그 프로젝트의 구조, 컨벤션, 함정을 이미 알고 시작한다.
- **자동 함정 대조** - 파일이나 심볼을 손대기 전에 노트북을 grep 해서, 과거에 밟았던 함정이 걸리면 본문을 펼쳐 설계에 반영한다. 같은 실수를 두 번 하지 않는다.
- **의도가 확정된 뒤에만 코드를 쓴다** - 인터뷰로 모호한 부분을 질문하고, 합의 내용을 살아있는 플랜 파일로 키운다. 플랜이 곧 스펙이다.
- **코드를 쓰기 전에 깬다** - 렌즈(구조 준수, 과설계, 중복, 정적 추적, 정합성)를 나눠 든 서브에이전트들이 플랜을 적대적으로 리뷰한다. 치명적 지적은 생산 전에 잡힌다.
- **검증까지 완주한다** - 만들고 끝이 아니라, 의도대로 동작할 때까지 검증-수정을 반복하고 마지막에 변경 요약과 보고서를 남긴다.
- **토큰 비용이 관리된다** - 서브에이전트 모델/effort 배치표, 인덱스 기반 점진 로딩, 대량 출력의 파일 리다이렉트로 메인 컨텍스트를 작게 유지한다.

## 빠른 시작

```bash
git clone https://github.com/FuJiGraphics/n-worker.git ~/.claude/skills/n-worker
```

Claude Code 세션에서 프로젝트 폴더를 열고:

```
/n-worker 인벤토리에 아이템 잠금 기능 추가해줘
```

첫 발동 시 프로젝트 등록 질문(슬러그, 스택, 컨벤션 문서 위치)에 답하면 노트북 골격이 만들어지고, 이후 세션부터는 자동으로 로드된다.

> 단순 질문이나 한 줄 수정에는 쓰지 않는다. 이 스킬은 "의도 확정과 검증에 왕복을 쓸 가치가 있는" 무거운 작업 전용이다.

## 동작 방식 - 6단계 파이프라인

```
P0 컨텍스트    노트북 로드 → 프로젝트 식별 → 작업 무게 확인
P1 인터뷰      질문 ↔ 답 ↔ 플랜 갱신 ↔ 병렬 조사 - 의도가 수렴할 때까지  [이 구간엔 파일 편집 잠금]
P2 사전 리뷰    난이도 판정 → 적대 리뷰(렌즈) → 취합 → 플랜 승인
P3 생산        복제 후 적응 - 기존 구현을 본떠 차이만 바꾼다. 대형 묶음은 서브에 위임
P4 검증        자동 검증 반복 - 로그는 발췌로만, 의도대로 동작할 때까지
P5 기록과 보고  배운 것을 노트북에 기록 → 변경 요약 표 → (선택) pdf/html 보고서
```

핵심 설계 결정 몇 가지:

- **P1~P2 편집 잠금.** 플랜이 승인되기 전에는 프로젝트 파일을 읽기만 한다. 코드가 먼저 쌓이는 사고를 구조적으로 막는다.
- **리뷰는 생산 전에 한 번뿐.** 생산 후 정적 리뷰가 없는 대신, 리뷰 입력이 "쓸 코드"가 되도록 파일별 변경 계획과 코드 초안을 플랜에 먼저 적는다.
- **복제 후 적응이 생성보다 우선.** 처음부터 새로 짜지 않고 그 프로젝트에서 가장 가까운 기존 구현을 본뜬다. 컨벤션은 저절로 따라온다.
- **읽은 것만 진실.** 노트북도 "과거에 검증된 기록"일 뿐, 동작을 걸기 전에는 라이브 코드로 다시 확인한다.

## 3층 노트북 - 장기기억의 구조

| 층 | 내용 | 예 |
|---|---|---|
| `notebook/projects/<슬러그>/` | 프로젝트 고유 (구조, 진입점, 컨벤션 위치) | "이 프로젝트의 피해 처리는 단일 진입점만 경유한다" |
| `notebook/stacks/<스택>/` | 엔진/프레임워크 일반 (unity, react 등) | "이 엔진의 에디터 API 는 들고 있던 참조를 무효화한다" |
| `notebook/common/` | 스택 무관 (도구 함정, 일반 원칙) | "이 CLI 의 인자는 조용히 유실된다" |

- 층은 "이 사실이 어디까지 일반화되는가"로 가른다. 기록, 승격/강등, 정비는 전담 서브에이전트(curator)만 한다 - 쓰기 창구가 하나여야 규율이 갈라지지 않는다.
- 기록 게이트: 조사 비용을 치르고 알아낸 것, 사용자가 말해줘야만 알 수 있는 것만 기록한다. 코드를 열면 몇 초에 확인되는 것은 기록하지 않는다.
- 전량 로드는 하지 않는다. 얇은 인덱스만 읽고 본문은 이번 작업에 걸릴 때만 펼친다.
- 노트북은 설치한 기기에서 자란다. `.gitignore` 가 누적 지식을 추적에서 빼므로 개인 프로젝트 정보가 레포에 섞이지 않는다.

## 선택 설정 - 노트북 게이트 (PreToolUse 훅)

"파일을 고치기 전에 노트북을 대조한다"를 스킬 지시가 아니라 하네스 수준에서 강제할 수 있다. `~/.claude/settings.json` 에:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit|NotebookEdit",
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$HOME/.claude/skills/n-worker/scripts/nb-gate.sh\"",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

- `scripts/nb-gate.mode` 가 `shadow` 면 기록만 하고 막지 않는다(기본값). `block` 으로 바꾸면 대조 기록 없는 프로젝트 파일 수정이 거부된다.
- 훅 없이도 스킬은 동작한다 - 게이트는 규율의 보험이다.

## 폴더 구조

```
n-worker/
├── SKILL.md               # 진입점 - 파이프라인 본문과 준칙
├── references/            # 단계별 상세 절차 (점진 로드)
│   ├── interview.md       #   P1 인터뷰, 질문 설계, 수렴 판정
│   ├── plan.md            #   플랜 파일 포맷
│   ├── review.md          #   P2 난이도 판정, 렌즈 카탈로그
│   ├── produce.md         #   P3 복제 후 적응, 위임 명세
│   ├── verify.md          #   P4 검증, 로그 판독, 핸드오프
│   └── report-render.md   #   html/pdf 보고서 규격
├── agents/
│   ├── curator.md         # 노트북 쓰기 전담 서브 (등록/기록/정비)
│   └── reporter.md        # 결과 보고서 생성 서브
├── scripts/
│   ├── nb-load.sh         # P0 노트북 로더 (registry + 3층 인덱스 1방 로딩)
│   ├── nb-grep.sh         # 함정 대조 (3층 인덱스 grep + 히트 본문 동봉 + 로그)
│   ├── nb-gate.sh         # PreToolUse 게이트 (선택)
│   └── open-artifact.sh   # 산출물 열기 (md 를 에디터로)
├── notebook/              # 장기기억 (시드 골격 - 설치 후 여기서 자란다)
└── assets/                # html 보고서 템플릿
```
