# 플랜 파일 포맷

`$WORK/plan.md`가 원본이다. 기본은 Markdown 하나이며 사용자 요청 없이는 열기나 HTML 생성을 하지 않는다. 짧은 작업은 대화의 작업 요약으로 충분하고, 다단계/위임 작업은 파일을 유지한다.

## 1. 최소 구조

```markdown
# <작업>
상태: 조사 / 구현 / 검증 / 완료 / 차단
작업 폴더: <절대경로>

## 목표와 범위
- 목표, 수정 범위, 유지할 기존 동작
- 위험: 낮음 / 일반 / 높음 - 이유
- 승인: 사용자 실행 요청으로 충족 / 추가 승인한 내용 / 미승인 사항

## 변경 방식
| 대상 | 변경 | 기존 구현/공유 계약 |

## 결정과 근거
- 결과를 바꾸는 결정과 근거만
- 관련 지침, 라이브 근거, 사용한 notebook lesson 경로
- 노트북 검색: <대상 묶음과 log 위치, 또는 히트 0>
- 중요한 미정/제한: <없음 또는 목록>

## 검증
| 검사 | 대상/실행 명령 | 결과와 근거 | 미검증 범위 |
- 위험 기반 리뷰: 생략 근거 / 담당 범위와 횟수 / 남은 지적

## 남은 일
- 차단 요인, 사용자만 확인할 표면, 필요한 후속 작업
```

## 2. 갱신 규칙

- 바뀐 절만 Edit한다. 초안 코드를 플랜에 먼저 구현하지 않는다. 공유 API처럼 합의가 필요한 계약만 코드 조각으로 명시한다.
- 결정 로그는 번복이나 되돌리기 어려운 트레이드오프만 남긴다. 사소한 선택과 모든 조사 과정을 기록하지 않는다.
- 노트북 대조는 작업 단위로 남긴다. 파일별 승인용 빈칸, 전환마다 재검색, 검색 결과 복사는 하지 않는다.
- 검증 결과는 계획과 구분한다. 미실행 명령을 통과한 것처럼 표시하지 않는다.
- 리뷰를 위임할 때 실제 변경 목록과 세션 기준 diff 경로, 검증 결과를 최신으로 맞춘다. 다른 작업자의 변경은 리뷰 범위 밖이라고 명시한다.
- 사용자 승인에 필요한 내용만 대화로 요약한다. 파일 전문을 대화에 이중 출력하지 않는다. 파일을 못 보는 환경이면 결정에 필요한 상세만 대화로 제공한다.
- 보고서는 플랜을 위해 존재하는 것이 아니다. 나중에 보고서를 채우려고 현재 필요 없는 절, 대안, 다이어그램을 만들지 않는다.
