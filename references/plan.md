# 플랜 파일 포맷

> 플랜은 사용자와 함께 만들어가는 문서다. 언제 열어도 현재 상태가 정확해야 하고, 장식이 아니라 판단 재료이므로 간결해야 한다.
> 파일 위치: `$WORK/plan.md` 가 유일한 원본이다. html 추적 모드면 `$WORK/plan.html` 을 병행한다. (`$WORK` 는 P0 에서 기억한 리터럴 절대 경로다.)
> P2 말미의 승인은 파일을 열어주는 것으로 끝내지 않는다 - 플랜을 대화에 렌더하고 `AskUserQuestion` 으로 받는다. 분량 규칙은 SKILL.md P2(요약 고정)가 기준이다.
> 플랜 파일은 작업 메모이므로, 본문 항목에 밀도 있는 압축 표기를 써도 된다(구조와 제목은 아래 뼈대 유지).
> **html 생성 규칙(plan.html 포함)과 결과 보고서 규격은 [report-render.md](report-render.md) 에 있다.** 메인은 html 추적 모드(②)를 고른 세션에서만 그 파일을 읽고, 보고서 절은 reporter 서브만 읽는다 - md 추적 세션의 메인이 로드할 이유가 없는 분량이라 분리했다.

## 1. plan.md 구조 (항상 이 뼈대를 쓴다)

```markdown
# 플랜: <작업 한 줄>
상태: 라운드 N | 인터뷰 중 / 리뷰 중 / 생산 중 / 검증 중 | 난이도: 경량/표준/중 - <근거 한 줄> | 갱신: <ISO 시각>
작업 폴더: <$WORK 절대 경로 - 컨텍스트 압축을 견디는 백업>

## 확정 (결정 + 근거)
- <결정> - 근거: <사용자 답 / file:line / 노트북 항목>

## 미정 (다음에 물을 것 / 조사할 것)
- <항목> - 왜 미정인가

## 변경 설계 (파일별)
| 파일 | 무엇을 | 방식(레퍼런스) | 노트북 대조 |

## 코드 초안 (P2 입력 - 구조/시그니처/핵심 분기 수준)
```<언어> ... ```

## 흐름 (필요할 때만 - 억지로 그리지 않는다)
텍스트 화살표 한 줄(A -> B -> C) 또는 표. 정식 SVG 다이어그램은 보고서에서 그린다.

## 검증 계획
- 자동 검증: <수단>  - 채택 카드: <목록>  - 회귀 경계: <유지할 동작>
- 위험 케이스: <④ 정적 추적이 먼저 넣을 상위 위험 시나리오 - 인터뷰에서 드러난 것>

## 리스크/우려 (P2 리뷰 결과 반영)
- <우려> - 상태: 열림 / 사용자 수용 / 해소(어떻게)

## 결정 로그 (번복 포함 - 왜 바뀌었는지 한 줄)
- R3: <결정> ← <이유>
```

- 라운드 갱신은 **바뀐 절만 고친다**(Edit) - 매 라운드 전체 재작성은 출력 토큰과 컨텍스트를 함께 낭비한다. 설계가 구조적으로 재편될 때(번복, 치명 지적 반영)만 전체를 다시 쓴다. 어느 쪽이든 불변식은 같다: **뒤집힌 결정이 본문에 남아 있으면 안 된다.** 부분 갱신 뒤에는 확정/설계 절을 훑어 모순 항목이 남았는지 확인하고, 번복의 흔적은 결정 로그에만 남긴다.
- **변경 설계 표의 `노트북 대조` 칸은 P2 승인 문항을 내기 전에 전부 채운다**(SKILL.md 준칙의 노트북 대조 규율). 값은 걸린 lesson 경로 또는 `히트 0` 이고, 빈칸은 "확인 안 함"을 뜻한다. 행이 추가되거나 대상 파일이 바뀌면 그 행의 칸을 비우고 다시 대조한다.
- 코드 초안은 "리뷰할 수 있는 최소 수준"까지만 적는다. 전문 작성은 P3 의 일이다.
- 결정 로그와 리뷰 결과는 나중에 보고서의 원재료가 된다. "왜 그렇게 했는지"를 지금 한 줄이라도 남겨두지 않으면 보고서 쓸 때 복원할 수 없다.
- **결정 로그에 올릴 것을 고르는 기준은 셋 다 성립할 때다:** ① 되돌리기 어렵다(나중에 마음을 바꾸는 비용이 크다), ② 맥락 없이 보면 놀랍다(나중에 읽는 사람이 "왜 이렇게 했지"를 묻는다), ③ 실제 트레이드오프의 결과다(대안이 진짜 있었고 이유가 있어 하나를 골랐다). 하나라도 빠지면 결정 로그가 아니라 확정 절의 한 줄로 끝낸다. 번복은 이 기준과 무관하게 항상 남긴다.
