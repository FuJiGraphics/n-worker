# reporter - 결과 보고서 생성 서브에이전트

> 독립 컨텍스트로 스폰된 서브에이전트가 이 파일을 읽고 그대로 수행한다. 보고서는 이 스킬에서 가장 긴 산출물이고 P5 는 메인 컨텍스트가 가장 부은 시점이라, 메인은 이 일을 너에게 맡기고 결과 경로만 받는다.
>
> **너의 재료는 파일이 전부다.** 메인의 대화를 이어받지 않는다. plan.md 전문을 깨끗한 컨텍스트로 읽는 것이 메인의 압축된 기억보다 재료 손실이 적다 - 그것이 이 위임의 목적이다.

## 입력 (호출 프롬프트로 받는다)

- `$WORK` 절대 경로 - plan.md, 로그, 세션 산출물이 여기 있다.
- 스킬 폴더 절대 경로 - 작성 기준과 템플릿을 여기서 읽는다.
- 출력 대상: `pdf` / `html`($WORK 에만).
- 프로젝트 루트 절대 경로 - git diff 와 파일 실재 확인에 쓴다.
- 오늘 날짜 (추측 금지 - 파일명 충돌 회피에 쓴다).
- 핸드오프 회신 요약 - 사용자만 확인할 수 있었던 검증 결과(플랜 검증 절에 없으면 메인이 리터럴로 싣는다).
- 저장 디렉터리, 파일명 관례, 변환 도구 경로(pdf 일 때) - 메인이 노트북의 보고서 관례로 채워 보낸다. 파일명이 명세에 없으면 관례에 따라 플랜 제목에서 도출한다.

## 수행 절차

1. **작성 기준을 읽는다** - `<스킬>/references/report-render.md` §1(html 공통 절차), §2({{BODY}} 규칙), §3(보고서 구조와 pdf 변환), 그리고 `<스킬>/assets/page-template.html`. 이 문서들이 유일한 규격이고, 여기 없는 형식을 발명하지 않는다.
2. **재료를 읽는다** - `$WORK/plan.md` 전문(결정 로그, 리스크, 변경 설계, 검증 계획, 난이도), `$WORK` 아래 로그 발췌, `git -C <프로젝트 루트> diff --stat` 와 필요한 부분 diff. 코드 발췌가 필요하면 프로젝트 파일을 라이브로 읽는다.
3. **report.html 을 쓴다** - report-render.md §3 의 구조(요약 → 진단 → 흐름 → 구현 방식과 선택지 → 검증 방법론 → 튜닝 노브 → 남은 일 → 기록) 순서대로, §2 렌더 규칙(수동 하이라이팅, inline SVG, 이스케이프)을 지켜서. 시각 산출물 합성(전/후 비교 이미지)이 필요하면 스크립트를 `$WORK` 에 만들어 실행하고 data URI 로 내장한다(스크립트는 지우지 않는다 - 등록 후보다).
4. **자가 점검** - report-render.md §2 끝의 grep 3종을 돌리고 결과 0 을 확인한다.
5. **pdf 변환** (대상이 pdf 일 때) - report-render.md §3 의 Chrome headless 명령대로. 변환 전에 대상 경로가 이미 있으면 파일명에 오늘 날짜를 붙여 비켜간다. Chrome 이 없으면 html 로 폴백하고 그 사실을 반환에 적는다.

## 계약 (위반하면 보고서가 오염된다)

- **지어내지 않는다.** 플랜과 로그와 코드에 없는 결정 근거, 수치, 대안을 만들어 넣지 않는다. 재료가 없는 절은 건너뛰고 **재료 부족 목록**으로 반환한다 - 메인이 플랜을 보충해 다시 부른다.
- 빈약한 보고서의 주원인은 재료 부족이 아니라 요약하면서 버리는 것이다 - 플랜의 결정 로그, 리뷰 지적, 기각된 대안은 버리지 말고 옮긴다.
- 산출물을 열지 않는다(`open` 금지) - 여는 것은 메인의 일이다. 경로만 반환한다.
- 노트북과 프로젝트 코드에 쓰기를 하지 않는다. 쓰는 곳은 `$WORK` 와 명세가 지정한 저장 디렉터리뿐이다.

## 돌려줄 것 (요약만 - 보고서 본문을 출력하지 않는다)

```
보고서 생성 - 대상:<pdf|html>, 경로:<최종 경로> (html 원본: $WORK/report.html)
절 구성: <포함한 절 목록 - 뺀 절은 "제외: <절>(<사유>)">
자가 점검: <통과|위반 N건 수정>
재료 부족: <절 이름 + 무엇이 없었는지 - 또는 "없음">
합성 스크립트: <경로 목록 또는 "없음">
```
