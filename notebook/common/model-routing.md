# model-routing - 서브 모델과 effort 를 고를 때 보는 사실 목록

> 서브를 스폰하기 직전에 메인이 보는 파일이다. **이 파일이 낡으면 스킬 전체가 낡는다** - 스킬 본문에는 모델 이름도 버전도 박지 않고, 배치 결정은 전부 여기를 근거로 메인이 내린다.
> 층은 common 이다(어느 스택/프로젝트에서도 같은 사실).

```
checked: 2026-09-02
갱신 트리거 (하나라도 걸리면 curator model-refresh 를 스폰한다):
  ① 세션 모델 이름이 아래 §2 표에 없다 - 새 세대가 나왔다는 가장 정확한 신호다
  ② checked 가 60일 이상 지났다
  ③ 별칭(`'fable'`/`'opus'`/`'sonnet'`)이 스폰에서 거부되거나 다른 세대를 가리킨다
  ④ 사용자가 갱신을 요청했다
```

## 1. 라우팅 원칙 (모델 세대가 바뀌어도 유지된다 - 실측 기반)

- **티어를 가르는 질문은 하나다: 답이 이미 코드 안에 있는가?** 있으면(찾기, 대조, 실증) 중간 티어, 없으면(반사실 추론, 놓친 분기 상상, 설계 판단) 한 티어 아래 플래그십. 판단 근거가 file:line 으로 끝나는 일과 추론으로 끝나는 일을 가르는 것이다.
- **배치는 상대적이다.** "세션 모델 = 최상위(메인 전용)", "한 티어 아래 최신 플래그십", "중간", "최하위 경량" 네 자리로 읽는다. 특정 이름에 의존하지 않는다.
- **model 은 항상 명시한다.** 생략하면 세션 모델을 상속해 전 서브가 최상위 티어로 돈다.
- **세션 모델과 동급 이상의 서브**가 필요하다고 판단되면 `AskUserQuestion` 으로 먼저 승인을 받는다(비용이 사용자 몫이다).
- **표 값이 기본값이다.** 벗어난 값을 쓸 때만 플랜 결정 로그에 근거 한 줄을 남긴다(난이도, 회귀 표면, 실패 비용, 그 서브가 실제로 할 일의 무게). 근거 없는 이탈은 표 값으로 되돌린다.

## 2. 현재 세대 매핑 (갱신 대상 - 여기가 낡는 부분이다)

| 별칭 | 현재 가리키는 세대 | 모델 id | §1 의 네 자리 | 이 스킬에서 쓰는 자리 |
|---|---|---|---|---|
| `'fable'` | Fable 5.1 (스폰 별칭 해석은 미확인 - 아래 참조) | `claude-fable-5-1` | 최상위(메인 전용) | **서브로 쓰지 않는다** - Opus 위 티어라 어느 서브에 붙여도 §1 의 "세션 모델과 동급 이상" 승인 규칙 대상이다 |
| `'opus'` | Opus 5 | `claude-opus-5` | 한 티어 아래 최신 플래그십 | 위임 생산, curator, reporter, 구조 조사, 추론형 렌즈(① 구조 준수, ② 과설계, ④ 정적 추적) |
| `'sonnet'` | Sonnet 5 | `claude-sonnet-5` | 중간, 최하위 경량 겸임 | 조사형 렌즈(③ 중복, ⑤ 정합성), P1 존재/위치 probe, 로그 판독, 판단 없는 기계 작업(벌크 스타일 교정, 대량 존재 확인, 로그 1차 필터) |

- 별칭은 **세대 자동 추적**이다 - 새 세대가 출시되면 별칭이 자동으로 최신을 가리키므로, 스폰 코드에는 별칭만 쓰고 id 는 쓰지 않는다. 이 표의 id 칸은 "지금 무엇을 가리키는가"를 사람이 확인하는 용도다.
- 별칭 셋(`'fable'`/`'opus'`/`'sonnet'`)은 2026-09-02 확인 시점에 모두 유효하다. 서브 스폰의 `model` 파라미터가 받는 값이다. 폐지나 의미 변경은 없다(트리거 ③ 미발동).
- **미확인 - 스폰 별칭 `'fable'` 이 Fable 5.1 과 Fable 5 중 무엇을 가리키는가.** 벤더 레퍼런스의 이름 해석 표는 "fable" 을 `claude-fable-5-1` 로 해석하지만 그것은 API 모델 문자열 해석이고, 하네스의 서브 스폰 별칭 해석과 같은 층이라는 근거는 없다. **어느 쪽이든 자리는 같으므로 배치 판단은 바뀌지 않는다** - 둘 다 최상위 티어이고 per-token 가격도 같다.
- `'opus'` → Opus 5 는 라이브로 확인됐다. 이 갱신을 수행한 curator 서브(§3 고정 배치대로 `'opus'` 스폰)의 세션 모델이 Opus 5 (`claude-opus-5[1m]`)로 보고됐다.
- **Fable 5.1 은 Fable 5 의 후속이고 같은 티어, 같은 per-token 가격이다.** 티어 자리 이동은 없다 - Opus 5 는 그대로 "한 티어 아래 최신 플래그십" 자리다.
- **Fable 5.1 은 Opus 위 티어다**(Mythos-class, 일반 출시된 모델 중 최고 능력 티어). 같은 티어에 Project Glasswing 한정 Mythos 5.1(`claude-mythos-5-1`)이 있고 능력, 가격, API 표면이 Fable 5.1 과 같은 기반 모델이다. 이전 세대 Fable 5(`claude-fable-5`)와 Mythos 5(`claude-mythos-5`)도 계속 서빙된다 - 세션 모델 이름이 이 넷 중 무엇으로 보여도 트리거 ①(새 세대)이 아니라 이 자리다.
- 모델 id 는 날짜 접미사 없는 문자열이 완성형이다. `claude-haiku-4-5-20251001` 처럼 날짜가 붙은 형태는 스냅샷 핀이며 같은 모델을 가리킨다(레퍼런스에서 dated full id 가 따로 있는 것은 Haiku 4.5 뿐이다).
- 세션 모델(메인)은 사용자가 `/model` 로 정하는 영역이다. 2026-09-02 확인 시점의 이 환경은 Fable 5.1 (`claude-fable-5-1`)이다. 2026-09-01 시점에는 Fable 5 (`claude-fable-5`), 2026-07-25 시점에는 Opus 5 (`claude-opus-5[1m]`)였다.
- 출처: 이 환경의 `claude-api` 스킬 레퍼런스(모델 표 cached 2026-06-24, `shared/models.md` 포함) + 이 환경의 시스템 컨텍스트(2026-09-02). 가격, 컨텍스트 한도, 벤치 수치는 이 파일에 옮겨 적지 않는다 - §4 의 1차 출처에서 그때 읽는다.

## 3. effort 규율

- 선택 가능한 값: `low` `medium` `high` `xhigh` `max`.
- **서브 effort 기본 상한은 `high` 다.** 실측(2026-07, 당시 세대)에서 xhigh/max 는 과추론과 wall-clock 만 늘었고 적발 품질이 오르지 않았다. 리뷰 깊이는 effort 가 아니라 케이스 상한(④ 의 N)으로 조절한다. 이 실측은 세대 종속이다 - 새 세대에서 상한을 넘길 근거가 생기면 플랜 결정 로그에 남기고 쓰되, 이탈이 반복되면 `model-refresh` 로 이 절을 갱신한다.
- **P3 위임 생산만 예외로 `effort` 를 생략해 세션 effort 를 상속한다.** 코드를 쓰는 일의 강도는 사용자가 `/effort` 로 정한 수준과 같아야 하고, 위임 여부가 코드 품질을 바꾸면 안 된다. 세션이 `max` 면 `xhigh` 로 명시해 내린다.
- **생산 외에는 생략 금지.** 생략은 곧 세션 effort 상속이다 - "메인이 정한다"는 "안 적어도 된다"가 아니다.
- 메인 세션의 effort 는 사용자 영역이므로 스킬이 건드리지 않는다.
- **고정 배치 (스폰 지시가 이 절을 가리킨다):** curator = `'opus'`, effort 는 register/model-refresh/harness-refresh 가 medium, record/targeted/sweep 이 high(큐 데몬 `scripts/curator-daemon.sh` 가 `claude -p --model opus --effort <이 값>` 으로 띄운다). **curator 는 하위 서브를 쓰지 않는다** - 헤드리스 `claude -p` 안에서 서브가 권한과 도구 제한을 물려받는지 미문서이고 실측(2026-09-03)에서 서브의 쓰기가 전부 거부됐다. 사용자 결정(2026-09-03): 서브는 없는 셈 친다(harness-routing.md #12). reporter 와 P3 위임 생산 = `'opus'`, effort 생략(세션 상속, 세션 `max` 면 `xhigh` 명시). 벌크 스타일 교정 = `'sonnet'`, effort low.

## 4. 1차 출처 순서 (갱신할 때 이 순서로 읽는다)

1. **이 환경의 `claude-api` 스킬** - 모델 id, 가격, params, effort/thinking, 마이그레이션 레퍼런스. 웹보다 싸고 정확하며 벤더 1차 정보다. 모델 관련 사실은 기억으로 답하지 말고 이것부터 읽는다.
2. **벤더 공식 문서** - 모델 카드, 가격 페이지, 릴리스 노트. 여기까지가 "사실"로 적을 수 있는 범위다.
3. **3자 벤치마크와 커뮤니티 보고** - 참고로만 쓴다. 적을 때는 `[참고]` 표기 + URL + 조회일을 함께 적고, 이 파일의 §1 원칙을 뒤집는 근거로는 쓰지 않는다(원칙은 이 스킬의 실측 기반이다).

**확인하지 못한 것은 적지 않는다.** 빈칸으로 두고 "미확인"이라고 쓰는 것이 추측을 적는 것보다 낫다 - 이 파일의 오류는 이후 모든 세션의 배치를 오염시킨다.
